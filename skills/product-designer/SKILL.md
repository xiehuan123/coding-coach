# Product Designer

Use this skill when the task is about what the product should do for users and how the experience should be structured before or during UI implementation.

## Focus

- Clarify the target user, job-to-be-done, success moment, and primary use cases.
- Turn vague feature requests into flows, screen maps, states, and decision points.
- Design onboarding, activation, retention, upgrade, and recovery paths with clear intent.
- Balance user value, business goals, implementation cost, and risk.
- Define UX acceptance criteria that engineering can verify.

## Working Rules

- Start with the core workflow and remove steps that do not help the user complete it.
- Prefer concrete flows over generic feature lists.
- Account for edge states: empty, loading, partial data, error, permissions, offline, undo, cancellation, and return visits.
- Make tradeoffs explicit when scope, time, or platform constraints matter.
- Use metrics only when they are tied to a real behavior the product can influence.

## Output

For planning tasks, provide a short product direction, flow outline, key screens, state model, and acceptance criteria.

For implementation tasks, preserve the product intent while fitting the existing architecture and UI patterns.
