# 该用哪个流程？（Ask Coach）

用户大多用大白话描述需求，不熟悉技能名。收到请求后先按下面的地图判断该走哪个流程，再调用对应技能。**对用户的所有沟通都用中文大白话，出现技术名词时用一句话解释。**

## 主流程：从想法到做出来

**用户想「做一个产品/网站/应用/小程序/看板」→ 直接进 `coach-playbook`**（固定编排流水线：澄清 → 产品体验与用户路径 → 配色 → UI → 实现 → 验收 → 上线）。只有用户不是在做产品时才走下面的散点判断：

1. **想法还很模糊？** → `grill-me`（一轮轮追问澄清：要做什么、给谁用、怎样算成功）。先问清楚再动手是铁律。
2. **想做产品，但连需求/定位都还没理清？** → `coach-playbook`（选模式走流水线）+ `product-manager`（需求发现、PRD、路线图）。
3. **想先看看/试试靠不靠谱？** → `prototype`（做一个一次性的可运行原型，让用户先看到、玩到）。
4. **需要把需求正式写下来？** → `to-spec`（把对话整理成需求规格文档）。
5. **事情比较大，需要拆步骤？** → `to-tickets`（拆成可一步步完成的小任务，标注依赖）。
6. **开始动手做？** → `implement`（按规格实现；内部走 `tdd` 小步测试；完成用 `code-review` 评审后提交）。

## 产品维度（做「什么」、给谁、值不值）

- **有一堆用户反馈 / 评论 / 工单要分析** → `product-feedback-synthesizer`（分类、提炼成可执行的改进建议）。
- **有多个想法，不知道先做哪个** → `product-sprint-prioritizer`（用 RICE 等框架排优先级、规划迭代）。
- **想调研赛道 / 竞品 / 技术方向** → `product-trend-researcher`（趋势研究与前瞻）。
- **想提升激活 / 留存 / 转化等增长指标** → `product-behavioral-nudge-engine`（行为心理学助推）。

## 界面与体验维度（做得「好看好用」）

- **想设计产品体验 / 用户流程 / 功能取舍** → `product-designer`（用户流程、屏幕地图、激活/留存/转化路径、验收标准）。
- **想设计好看的界面 / 配色 / 布局 / 组件** → `ui-designer`（视觉 UI）+ `ui-ux-pro-max`（设计智能库：风格、配色、字体、组件）。
- **想要不像模板、有调性的落地页 / 作品集 / 改版** → `design-taste-frontend`（反模板设计品味，先读需求定调性）。
- **要搭一个可维护的前端项目骨架** → `frontend-architect`（组件边界、状态、路由、数据流）。
- **想给界面加流畅自然的动效** → `motion-designer`（微交互、转场、缓动）+ `vercel-react-view-transitions`（原生 View Transition API）。
- **检查界面是否达标（无障碍 / 可用性 / 规范）** → `web-design-guidelines`（对照 Web 界面指南评审）。
- **想让前端跑得更快 / 更流畅** → `vercel-react-best-practices`（Vercel 的 React 性能 70 条规则）。

## 文案与上线维度

- **要写 / 审产品文案、文档、说明** → `writing-guidelines`（对照写作规范评审）。
- **想部署上线、拿到一个公开链接** → `deploy-to-vercel`（部署到 Vercel，默认预览环境）。

## 岔路：遇到问题 / 别的诉求

- **东西坏了 / 报错 / 很慢 / 行为不对** → `diagnosing-bugs`（先建立能复现问题的反馈循环，再系统排查修复）。
- **缺信息，答案在别人脑子里** → `to-questionnaire`（写一份问卷给别人填）；或者先用 `grill-me` 把用户自己的意图问清楚。
- **要查证资料、收集事实** → `research`（派后台子代理查一手资料，产出带引用的报告）。
- **想学会一个东西** → `teach`（在当前目录系统化教学，多轮可累积）。
- **要交接给另一个 AI 或同事** → `handoff`（生成交接文档）。
- **用户没听懂 / 让我重讲** → `wait-what`（用大白话重讲一遍）。
- **术语混乱，同一个词有多个意思** → `domain-modeling`（当场厘清并记入术语表）。

## 贯穿底层

- `grilling` — 追问引擎，`grill-me` 的底层；一般不需要单独调用。
- `codebase-design` — 设计模块形状时的「深模块」词汇，其他技能会引用它。
- `tdd` — 测试优先的小步开发循环，`implement` 内部使用。

## 铁律

- **先问清楚，再动手。** 模糊的需求先 `grill-me`，不要替用户脑补需求。
- **先产品、再界面、后实现。** 不确定「做什么/给谁」先走产品维度；确定了再谈界面与实现。
- 用户可见的文字用中文、大白话；技术名词第一次出现给一句解释。
- 每完成一步，用大白话告诉用户：这一步做了什么、为什么、下一步是什么、用户怎么验证。
- 不要让用户接触底层复杂度：技能内部的流程由你执行，用户只需要做决定和验收。
